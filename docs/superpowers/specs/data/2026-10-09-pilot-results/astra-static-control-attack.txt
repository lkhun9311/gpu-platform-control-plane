4. **The mechanism statistic counts unfinished prefills, including queued requests—not simultaneous prefill execution.**  
   `engaged` is set when a request enters the engine’s **waiting queue**. `pace` counts overlapping intervals from that timestamp until first token. Consequently, “six contenders prefill at once” and “35% of the span” measure requests present without a first token, including requests receiving no tokens. They do not directly demonstrate six active prefills or the duration of token-budget starvation.

   The measured timing also starts at the scheduler’s `add.mono`, whereas the simulation uses `arrival_wall`. These are distinct: the diagnostic’s first contender has approximately **32 ms** between recorded arrival and scheduler insertion. That distinction matters when discussing a narrow timing tolerance.

6. **There is a concrete timer-handling defect in the static-control simulation.**  
   When the engine becomes idle, its next-event calculation includes arrivals and notifications but **omits the next spacing deadline**. It can jump past a held contender’s release time. Later, the rule backdates the forwarding timestamp, but engine execution still starts at the advanced clock. For example, an idle engine can skip a release due at 3 seconds until an unrelated arrival at 10 seconds. Deadline checks can also reject the request before that backdating occurs.

   This can penalize fixed spacing. I have not established whether it changes these particular archived figures; the existing spacing test keeps the engine busy and does not cover this case.

**My judgment on the control:** retain fixed spacing with the same cap as a legitimate baseline. Select its spacing on calibration data using a frozen objective and contender constraints, then evaluate on held-out traces—or compare the feasible tradeoff curves. Parameter sensitivity is a reason to specify that selection procedure, not evidence that a main study is uninformative. If longer prompts become the robustness experiment, include a static rule that scales spacing with known prompt work; otherwise the comparison also tests whether the control ignores request size.
